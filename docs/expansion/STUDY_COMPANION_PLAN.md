
# Catalyst pivot: AI study companion

## Context

Catalyst was built as a course platform (CHEM113, admin-written lessons). The owner judged that too narrow and not sure to succeed. Catalyst becomes an AI study companion: a student gives it their own material and gets a guided mini course back (notes, flashcards, quizzes), plus science tools. The design, mostly the input surfaces, is what blocks a closed beta, so design work is part of this plan, not a later polish.

Much of the pivot already exists in `backend/src/modules/lab/` and `frontend/src/pages/lab/`: study sets, notes, cards, quizzes, PDF and text build flow, AI drafts with a cache, a companion chat, daily AI usage rows, a service worker and a web manifest. The plan promotes that code to be the product and re-points the best course screens at it.

## Decisions from the interview

| Topic | Decision |
|---|---|
| Beta testers | About 20 university students in Ghana. Opens when the owner feels ready. |
| Subjects | Any subject works. Science gets the special tools (formulas, simulations). |
| Structure | A study set is a mini course: set > unit > lesson, generated by AI, editable by the student. Khan Academy style path and mastery. |
| Course code | Admin-written courses leave the product. The course outline and lesson screens are reused for sets. Course backend code stays in the repo, unmounted from navigation. |
| AI inputs (beta) | PDF and slides, pasted text or a topic name. Later: photo of notes, YouTube link. |
| AI provider | Gemini free tier only until production; no paid model until students pay. 2.5 Flash-Lite is deprecated: move to the newest free-tier Flash-Lite. See `docs/redesign/DESIGN_RESET_PLAN.md`. |
| Price | Beta is free with a daily cap. Log AI cost per user. Price set after beta: at least cost per paying user ÷ 0.6 (40% margin). |
| Social | Share by link and copy a shared set only. Circles, friends, challenges, boards and the community shelf are hidden. |
| Devices | Phone and laptop get equal weight. |
| Offline | Low-data mode, installable app. A set is saved to the device after generation: notes, flashcards and quizzes work offline. AI and editing need internet. |
| Design | StudyFetch is the main reference. All input surfaces are redesigned. Login and register get light polish. |

## What goes in, what goes out

**In for beta**
1. One-shot build: upload or paste, get a structured set (units, lessons, notes, cards, quizzes).
2. Set outline with mastery per unit (not started, familiar, proficient, mastered), driven by quiz results.
3. Lesson screen: notes, then flashcards, then a quick check.
4. Unit quiz and a whole-set test.
5. Mistakes become review cards (reuse `assessments/mistake.*`).
6. Ask-your-notes tutor (reuse `Companion.jsx`, `CompanionDrawer.jsx`, `lab/ai.controller.js`).
7. Review queue for due flashcards (exists).
8. Share by link, copy a shared set.
9. Streak. Offline study. AI usage log and daily cap.

**After beta**
Simulations library (5 to 8 hand-built, linked from matching sets), exam countdown plan, photo of notes, YouTube explainer, payments, public library.

**Out (hidden, code kept)**
Course catalog, admin course, lesson and test editors, question import, circles, friends, challenges, boards, community shelf, XP and levels, topics page. (Achievements come back with new badge images and an overhaul: see `docs/redesign/DESIGN_RESET_PLAN.md`, phase 7.) Admin keeps users, reports, analytics.

**Suggested, owner to confirm:** cut the five palettes to two. Fewer combinations to test and a stronger identity.

## Technical approach

### 1. AI provider (small)
- `backend/src/config/ai.js`: add a Gemini row to `MODELS`, make it the default, raise `maxInputChars` and `maxOutputTokens` (the current 12000 and 600 are too low for a whole set).
- `backend/src/utils/ai.js`: add a `gemini` function to `PROVIDERS`, update `isConfigured`, map Gemini's quota error to the existing `capacity` code. Add support for a file part so a PDF goes to Gemini directly. Callers keep using `complete()`.
- New env variable `GEMINI_API_KEY`. Update the backend README.
- Check Google's own pricing page for current free-tier limits before this step.

### 2. Set structure (the main backend change)
New light models in `backend/src/modules/lab/`, not a reuse of `Course`, `Unit`, `Lesson` (those carry admin publishing and version logic a student set does not need):
- `setunit.models.js`: `set`, `title`, `order`, `deletedAt`.
- `setlesson.models.js`: `set`, `unit`, `title`, `order`, `content` (Tiptap JSON, as `SetNote` uses today), `deletedAt`.
- Flashcards get an optional `setLesson` reference. Quizzes belong to a unit or to the set, matching the standing rule that tests stay tied to unit and course level. The lesson's quick check draws from its unit's questions.
- `setmastery.models.js`: one row per user and unit, level computed from quiz results.
- Routes added to `studyset.routes.js`, reorder routes declared before `/:id` routes, owner checks as in `studyset.controller.js`.
- Existing flat sets: a small migration wraps each set's single note in one unit with one lesson.

### 3. Build flow
- `setbuild.controller.js` and `utils/aiDrafts.js`: two steps. Step one asks for an outline (units and lesson titles). Step two fills each lesson (notes, cards, questions). Keeps each request small and lets the screen show progress per lesson.
- Keep the `AiDraft` hash cache and the `build.status` field.
- `aiLimiter.js` and `AiUsage`: add the daily per-user cap and a platform cap. Token counts are already stored: add an admin view of cost per user.

### 4. Frontend
- Navigation in `components/layout/AppShell.jsx`: Home, Library, Review, Me. Remove hidden routes from `App.jsx` and `HeaderSearch.jsx`.
- `pages/learn/CourseOutline.jsx` and `pages/learn/Lesson.jsx` become the set outline and set lesson screens, reading set data. `pages/lab/LabSet.jsx` becomes the edit view of the same set.
- Home (`pages/learn/Courses.jsx`): continue where you stopped, due reviews, your sets, one clear "New set" action.

### 5. Offline
- `frontend/public/sw.js` already keeps opened lesson and outline reads. Extend `OFFLINE_API` to set outline, set lessons, cards and quizzes.
- Quizzes offline need answers on the device. The server-side-only grading rule is narrowed: it holds for content a student does not own. For the student's own set, answers ship with the saved set.
- Flashcard ratings and quiz results queue in IndexedDB and sync on reconnect.
- AI and edit controls show a calm "needs internet" state offline.

### 6. Design
- Run the `impeccable` skill against `PRODUCT.md` and `DESIGN.md` first: both must be rewritten for the new product before any screen work.
- Input surfaces, in this order: new set (upload, paste, topic), build progress, lesson notes editor, card editor, quiz question editor, tutor chat box, onboarding, settings.
- Rules already in `CLAUDE.md` stand: create first and edit in place, autosave, choose instead of type, content width 760 to 900 px, no form left open on a page.
- Each screen checked at 320, 360, 390, 768 and 1280 px.

## Phases (one step per session, as now)

1. **Product docs**: rewrite `PRODUCT.md`, `DESIGN.md`, `CLAUDE.md` and `docs/ROADMAP.md` for the pivot. New work branch from `main`.
2. **Prune**: hide the out-of-scope routes and navigation. No deletes.
3. **Gemini**: provider swap, limits, usage log, daily cap.
4. **Set structure**: models, routes, migration, README.
5. **Build flow**: outline then lessons, progress screen.
6. **Student path**: set outline, lesson, unit quiz, mastery.
7. **Input surfaces redesign**: the list in section 6.
8. **Home and Library redesign**.
9. **Offline**: service worker, sync queue.
10. **Beta readiness**: hosting, production cookies, a feedback form with the "what would you pay" question, the unverified checks listed in `CLAUDE.md`.

After beta: simulations, exam plan, photo and YouTube inputs, payments.

## Verification

Each phase follows the verification protocol in `CLAUDE.md` (launcher outside the repo, `catalyst_test` database, throwaway users, Playwright with a fresh context per viewport, one `CHECK name => result` line per check, cleanup).

Checks specific to this plan:
- Gemini: build a set from a real lecture PDF and from pasted text with `AI_MODEL` set to Gemini. `AI_PROVIDER=fake` still passes.
- Structure: a built set has units and lessons, another user gets 404 on every set route, a deleted set returns 404 for its lessons.
- Cap: the request after the daily cap returns the calm capacity message, and `AiUsage` shows the token counts.
- Offline: open a set online, switch Playwright to offline, read a lesson, rate cards, take a quiz, go online, confirm the results reached the server.
- Shared set: a copied set does not expose the owner's source material.
- `npm run build` in `frontend/` passes after each frontend phase.
